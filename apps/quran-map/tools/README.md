# Quran Map word-notes tools

Scripts that build and maintain `../gloss.json`, the essential-word notes the Quran Map reader underlines.
`gloss.json` is the single source of truth. Each note pairs quran.com's word-by-word English with a meaning
from التفسير الميسر and context from تفسير السعدي. Run every command from this folder with Python 3.

| File | What it does |
|---|---|
| `paths.py` | Shared paths and the source labels. |
| `fetch.py <first> [<last>]` | Downloads word-by-word English, al-Muyassar and al-Sa'di from api.quran.com into `cache/`. |
| `digest.py <surah> [--full]` | Prints each ayah's word positions, the word-by-word English and both tafsirs. `*` marks words that already have a note. |
| `build_gloss.py [--src f] [--out f] [-v]` | Re-derives each note's exact word (`w`) and word-by-word English (`wbw`), checks every key, writes the file. With `--src`/`--out` it checks a draft without touching the app. |
| `merge_parts.py <draft.json> …` | Merges reviewed drafts into `gloss.json` and rebuilds it. A draft key that already exists replaces the old note, which is how corrections go in. |
| `progress.py [--active 2-77]` | Regenerates `progress.html`, the per-surah dashboard. `--active` marks surahs being drafted. |
| `GLOSS_BRIEF.md` | The drafting rules and entry format, written so a helper agent can draft a batch on its own. |
| `progress.html` | The latest dashboard. A copy is published as a private claude.ai artifact. |

`cache/` and `parts/` are git-ignored: the cache can always be re-fetched, and drafts belong in the repo only once merged.

## Typical jobs

**Fix or improve one note.** Write `parts/fix.json` as `{"words": {"68:42:4": { …full entry… }}}`, then:

```
python build_gloss.py --src parts/fix.json --out parts/check.json -v
python merge_parts.py parts/fix.json
```

**Add notes for a surah** (or re-draft one with richer context):

```
python fetch.py 36
python digest.py 36 --full > parts/digest_36.txt
# draft parts/part_36-36.json following GLOSS_BRIEF.md, then
python build_gloss.py --src parts/part_36-36.json --out parts/check.json -v
python merge_parts.py parts/part_36-36.json
python progress.py
```

**Check the whole file** after editing `gloss.json` by hand: `python build_gloss.py` (needs `cache/` for the surahs touched; it keeps the stored word-by-word where the cache is missing).

## Entry format

```
"2:2:9": {
  "w": "…", "wbw": "…",            // generated by build_gloss.py, never typed by hand
  "tr": "lil-muttaqīn", "root": "و ق ي",
  "form_en": "…", "form_ar": "…",
  "en": "…",                        // English meaning
  "ar": "…",                        // Arabic meaning, from al-Muyassar
  "note_en": "…", "note_ar": "…",  // context, mostly al-Sa'di; may be ""
  "see": ["surah:ayah"],            // related ayahs, only when certain
  "src": ["wbw", "muyassar", "saadi"]
}
```

Keys are `surah:ayah:word`, where the word position counts tokens in the ayah text split on spaces. Standalone
pause marks such as ۖ count as tokens but are never chosen.

## Known gaps worth a future pass

- The digest trimmed al-Sa'di to 500 characters while the first full set was drafted, so some context notes rely on
  al-Muyassar alone or are empty. Re-draft those with `digest.py --full`.
- 68:42 سَاقٍ follows al-Muyassar and al-Sa'di. Other classical readings (e.g. at-Tabari reporting Ibn 'Abbas:
  "when matters become severe") could be added to the note.
- 37:130 is written as two tokens (إِلْ يَاسِينَ) but quran.com counts one word, so it is never glossed.
