// by the end you will

What you will build

  • A valid OKF bundle: one markdown file per concept, YAML frontmatter on top
  • A 20-line parser that reads the bundle with only the standard library
  • A knowledge graph that emerges from plain markdown links
  • A write-back habit that lets an agent keep the bundle current
These four promises map to the four modules. Everything serves one of them.
// the premise

The most portable format for agent context is the one every tool already reads.

No SDK. No runtime. Just markdown, files, and YAML frontmatter.

This is the OKF bet Google shipped in June 2026. We are going to build one from scratch.
module 01 / 04
// 01

One concept, one file

// the format

The whole spec fits on a slide

Each concept you want an agent to understand (a table, a dataset, a metric, a runbook) becomes one markdown file. The file path is its identity. Only one frontmatter field, type, is required.

// tip Reserved optional fields are title, description, resource, tags, and timestamp. Everything else is yours.
Minimally opinionated by design: the spec defines interoperability, not your content model.

One concept, one file

module 02 / 04
// 02

Parse a bundle

// the reader

Reading OKF needs no library

A consumer splits each file into its YAML frontmatter and its markdown body, then keeps the fields it cares about. Because it is just text, the whole reader is a few lines of standard library.

Contrast with a catalog API you would have to authenticate against and learn.

Split frontmatter from body

parser.py L12-24
text = path.read_text(encoding="utf-8")
meta: dict[str, str] = {}
body = text
if text.startswith("---"):
    _, fm, body = text.split("---", 2)
    for line in fm.strip().splitlines():
        if ":" in line:
            key, val = line.split(":", 1)
            meta[key.strip()] = val.strip()
links = re.findall(r"\[[^\]]+\]\(([^)]+)\)", body)  # [label](target.md)
return {"path": str(path), "type": meta.get("type", "?"), "links": links}
The regex pulls every markdown link target out of the body; those become graph edges in module 3.
// your turn

Run the parser

  1. Save parser.py next to your okf_sample/ folder
  2. Run python parser.py okf_sample
  3. Confirm each file prints its type and the links it points to
⏱ ~10 min
If a file prints type "?", the frontmatter did not parse. Usually a missing colon or dash.

module 04 / 04
// 04

Make it self-maintaining

// the llm-wiki loop

The bookkeeping humans hate, machines do well

A wiki decays because nobody updates cross-references. An agent does not get bored doing exactly that. Let it read the bundle, and let it write changes back as files in version control.

// guardrail Let agents propose edits as pull requests, not silent commits. Human review guards every change while the bundle keeps improving.
This inverts the economics of documentation: it can now improve under machine maintenance.
// your turn

Close the loop

  1. Add a log.md to the bundle recording today's change
  2. Write the one-line prompt you would give an agent to keep the bundle current
  3. Decide your write-back policy: direct edits, or pull requests only
⏱ ~10 min
End on policy, because the maintenance loop is where the value and the risk both live.
