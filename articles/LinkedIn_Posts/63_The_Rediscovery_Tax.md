Somewhere this week an agent worked out that your integration tests hang unless they run one at a time. It fixed the command, finished the job, and the session closed. The lesson went with it. Tomorrow another agent spends the same twenty minutes learning the same thing.

That knowledge dies in three places: the session, the agent, and the harness it runs inside. A lesson learned in one vendor's tool is saved in that vendor's format and read by that vendor's tools alone. The cost is not one rediscovery. It is one per agent, per harness, every time the fact is needed again.

The obvious fix is to save everything and let the next agent search it. The research says that is the wrong shape. Hu, Long and Wang found that short abstracted procedures transfer reliably while detailed recordings do not, and that when a bad memory does get retrieved it misleads mostly on the hard tasks, which is exactly where the help was needed.

So save the lesson, not the transcript. Keep it short too, because every item you publish competes for room in some future agent's context window. Volume is a cost, not an asset.

And the part worth remembering: a memory layer does not remove the problem. It moves it from what gets written down to what gets surfaced.
