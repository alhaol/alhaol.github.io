Architecture 2026-09-22

Save the lesson, not the transcript

Logging taught us to keep everything. Agent memory punishes you for it.

Observability trained a generation of engineers on one rule. Capture everything, index it, work out later what mattered. Storage is cheap, and the log you did not keep is the one you need at three in the morning.

That rule does not survive the move to agent memory. The reason is structural, not a question of cost.

The problem it is trying to solve is real

Somewhere in your company this week, an agent worked out that the integration tests hang unless they run one at a time. It fixed the command, finished the job, and the session closed. The lesson went with it. Tomorrow another agent spends the same twenty minutes learning the same thing.

That knowledge dies at three separate boundaries. The session, because an agent's working notes are thrown away when the task ends. The agent, because two agents on the same repository cannot see each other's findings. The harness, because a lesson learned inside one vendor's tool is saved in that vendor's format and read by that vendor's tools alone.

The cost is not one rediscovery. It is one per agent, per harness, every time the fact is needed again.

Keeping everything is the wrong fix

The obvious build is to store the recordings and let the next agent search for the closest match. Testing exactly that across sequential tasks in two agent benchmarks, Hu, Long and Wang found that short abstracted procedures transfer reliably while detailed recordings do not. The distilled procedure beats the verbatim log.

They also found the damage is not spread evenly. When a retrieved memory misleads an agent, it does so mostly on the hard tasks, which is where the help was needed. An easy task shrugs off a bad hint. A hard one follows it.

So a memory store filled with raw sessions is not a neutral asset waiting to be useful. It is a pile of dead ends and confident wrong turns sitting next to the one good discovery, and it will teach the next agent the mistakes with exactly the same authority.

The constraint moved, it did not leave

Here is the part worth sitting with. A memory layer looks like it escapes the old tradeoff between keeping what you know and taking in what is new. The same team found that it does not. The context window is finite, so old and new memories compete for room at the moment of retrieval. The hard part moves from what gets written down to what gets surfaced.

Which inverts the instinct observability gave you. Every item you promote competes for space against every other item you promoted. Volume is a cost, not an asset.

Three things follow. Instrument the runtime rather than asking agents to write their own summaries, because an agent asked to reflect does so when it has the least context left. Promote short procedures rather than transcripts, and pay for the distilling step instead of treating storage as the finish line. Give every promoted item an owner and an expiry date, because much of what an agent learns holds only until the next dependency upgrade, and a reviewed, confident, out of date instruction is worse than none at all.
